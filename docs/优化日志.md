## 2026-10-20 短分镜导不出来（`loudnorm` × 纯静音）＋ 导出面板偏好单一来源 — 台账 `docs/superpowers/plans/2026-10-19-export-canvas-single-source.md`

- **接的是昨天欠的 §六-9**：那颗「1 秒方案 `rc=234`」的既有缺陷，前一晚我在 shell 里扫分界点、五个时长**全红** ⇒ 复现命令与产品链路不同形，读数作废。这次改成沿**真产品链路**（`ExportService.export` → `FFmpegRunner.concat`）扫，再让 shell 台架**先复现出同一颗分界**（2.5s 红 / 3.0s 绿）才允许它做消融。
- **成因是三因合取**：ffmpeg 8.1 的 `loudnorm` 只剩线性模式，吃到**纯数字静音且不足 3s** 会吐 NaN ⇒ aac 拒收 ⇒ 整条导出死。有电平 1.0s 绿、−81dB 近静音 2.5s 绿、纯静音 6.0s 绿。**中毒单位是单条分镜不是成片总时长**：1s 静音＋4s 有声（总 5s，尺寸与时长两条闸都过）实测仍整条红 ⇒ 昨天的时长闸救不了它。
- **修族不修点**：规则落 Core（`LoudnessChainPolicy`：窗口 3s ＋ `needsSilenceProbe` ＋ `mustBypassLoudnorm`），`concat` 的音频支路判据从「有没有音轨」换成「有没有**可听**的音频」；静音口径取 `astats` 的 `RMS level dB: -inf`（**只认全零** ⇒ 作用面严格等于今天必然失败的那些，另各有"必须仍走 loudnorm"的对照腿）。仓内两处 `loudnorm` 住所只修了有复现的那一处，配音中间片那处未复现 ⇒ 没动，就地留账。
- **排除掉的路线（实测非推断）**：`loudnorm=…:linear=0` 仍 rc=234 且对有电平增益无影响（mean −15.3 dB 两写法一致）⇒ 8.1 上这颗开关是死的。
- **量到但**等拍**未落地**：音频链写的是 `aresample=44100,loudnorm=…`，而 `loudnorm` 内部抬到 192k 再输出、aac 上限 96k ⇒ **每一条成功导出的成片落盘都是 96000 Hz**（产品 stderr 直读＋ffprobe 复核）。把 `aresample` 挪到 `loudnorm` 之后即兑现（真素材 mean_volume −18.5 / −21.5 dB 两写法完全相同，max 差 0.1 dB）；因它改的是每一条交付件的采样率、而 96k 至今无平台侧受害证据 ⇒ 未动。
- **面板偏好单一来源**：四颗选择（交付目标／档位／编码器／质量）改为**只住 `@AppStorage`**，`exportConfig` 变派生计算属性，`@State` 那份持有已删除并由守卫钉住（含"复活 @State 必须被抓住"的变异腿）。还原规则一份（Core `init(persisted:fallback:)`：读不出来回落**调用方给的**缺省，不许 `allCases.first`），缺省值一份（`ExportConfig` 属性初值）。
- **台架账（生产码未动）**：加了第三组会 spawn 的渲染腿后，App 目标重现"失败集合会移动"的瞎红。对照：ES-I 单独绿、LC-I 单独绿、两条并跑一次红一次绿、全目标无闸红 1~2 条且两次都只在**一个**宿主实例内 ⇒ 根因是 **`.serialized` 只管单个 suite、不管 suite 之间**。修法：11 条渲染用例全部收进进程内 FIFO 闸 `withFFmpegBench`，并补上"抛出必记具名原因"；收闸后 21 条 0 红、连跑两次。
- **抓到一次假绿**：想用 `-parallel-testing-enabled NO` 消掉多实例，结果它把用例数收成 **0** 却报 **TEST SUCCEEDED** ⇒ 该读数作废。凡报"绿"必须先证 `Executed N tests` 里 N 不是 0。
- **变异腿逐条对上**：把 `mustBypassLoudnorm` 临时摘成恒 `false`（预读整份＋md5 核回还原），Core 只红该红的 3 条（参数化那条逐格报 2.9/2.5/1.0），App 只红 `LC-I-01`、`LC-I-02` 两条真渲染复现；`LC-I-03`（测探测本身）、ES-I（源无音轨）、以及两条"不许改道"的对照腿全部照绿 ⇒ 判据承重且作用面判断准确。
- **验证**：`swift test` 计数 1171 → 1183 passed／非 known 失败 0（新增 `LoudnessChainPolicyTests`、`DP · 持久化偏好还原`、`ES-08`，明细见台账 §四）；`check_app_build.sh` PASS（258 编译单元）；App 测试腿 21 条 0 红 ×2；`check_pbx_registration` ＋ 10 支 `check_*` 守卫全 PASS。
